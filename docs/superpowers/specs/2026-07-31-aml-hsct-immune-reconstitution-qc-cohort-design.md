# AML异基因造血干细胞移植后免疫重建：质控与纳排设计

## 1. 目标与临床边界

本项目使用2018-2025年AML造血干细胞移植电子病历，建立可审计、可复现的纵向免疫重建队列。设计目标不是先筛出一张“整齐的完整病例表”，而是：

1. 完整刻画移植后免疫恢复的时间、速度、个体差异和异常表型；
2. 评估患者、疾病、供者和移植因素对免疫恢复的影响；
3. 在严格保证时间顺序的前提下，研究免疫状态与感染、GVHD、复发和死亡的关联；
4. 为后续Landmark预测、竞争风险和时间依赖分析建立可信的数据底座。

所有原始病历只读保存，不覆盖、不删除。清洗后的值与原始值并存，所有排除、修正、单位换算和人工复核均保留审计记录。

## 2. 已确认数据范围

| 数据源 | 规模 | 患者覆盖 | 主要用途 |
|---|---:|---:|---|
| `移植信息.xlsx` | 2,820行，121列 | 2,820名AML患者 | 基线、移植、供者、并发症、结局与随访 |
| `检验数据.csv` | 约337.8万条逻辑记录，33列 | 2,819名主表患者 | 血常规、生化及少量免疫相关检验 |
| `免疫重建+免疫残留.xlsx` | 44,974条报告 | 2,798名主表患者 | 免疫重建、免疫残留和流式报告 |

三表患者交集为2,798人。移植主表含异基因2,813例、同基因4例、自体3例；均记录为首次移植。

## 3. 推荐队列架构

采用“宽入口总队列 + 分层质控 + 嵌套问题队列”。不以所有时间点均有检测作为主队列条件，避免因病情、住院和检测频率造成严重选择偏倚。

### 3.1 主队列

- 疾病：移植原发病为AML；
- 时间：移植日期位于2018-01-01至2025-12-31且可解析；
- 移植：首次异基因HSCT；
- 主键：患者编号和移植日期均有效；
- 预计规模：2,813人。

### 3.2 敏感性总队列

纳入全部2,820名首次HSCT的AML患者；同基因4例和自体3例不进入主要推断，但用于描述和敏感性分析。

### 3.3 不以年龄作总队列硬排除

除年龄小于0岁或大于120岁等不可能记录外，所有年龄先纳入。分析时按儿童、成人和老年分层，并增加成人限制队列作为敏感性分析。不能直接照搬参考论文的18-70岁标准，因为年龄是免疫恢复的重要决定因素。

### 3.4 嵌套分析队列

| 队列 | 最低要求 | 主要问题 |
|---|---|---|
| 纵向轨迹队列 | 移植后至少1次有效免疫检测；估计个体斜率时通常需至少2次 | 典型轨迹、恢复速度和异质性 |
| 早期恢复队列 | D0-D100至少1次有效检测 | 早期免疫恢复与感染、植活 |
| 中长期队列 | D101-D730至少1次有效检测 | T/B细胞恢复、慢性GVHD和长期免疫缺陷 |
| Landmark队列 | Landmark时存活且未发生目标结局；此前有有效免疫暴露 | D30、D60、D100、D180后结局预测 |
| 感染队列 | 免疫暴露、首次感染日期和随访日期可靠 | CMV、EBV、细菌、真菌等首次事件 |
| GVHD队列 | 免疫暴露和GVHD日期可靠 | 免疫恢复与急/慢性GVHD的双向关系 |
| 复发队列 | 复发状态、日期和移植前疾病状态可靠 | 免疫恢复与复发/GVL效应 |
| 生存队列 | 死亡状态、死亡日期、末次随访可定义 | OS、NRM及竞争风险 |
| 免疫表型队列 | 核心指标在至少2-3个不同时间有记录 | 快速、延迟、失衡等轨迹表型 |

## 4. 时间零点和时间窗

Day 0定义为造血干细胞回输日期。所有检验、报告、植活、感染、GVHD、复发、死亡和随访日期转换为相对移植天数。

| 阶段 | 时间窗 | 主要用途 |
|---|---:|---|
| 移植前基线 | D-30至D-1 | 基线免疫、疾病和近期治疗影响 |
| 极早期 | D0-D30 | 植活、先天免疫和早期感染 |
| 早期I | D31-D60 | T/NK早期恢复 |
| 早期II | D61-D100 | 经典早期移植结局窗口 |
| 中期 | D101-D180 | T/B细胞恢复和慢性GVHD起始 |
| 晚期 | D181-D365 | 免疫稳定化和长期感染风险 |
| 长期 | D366-D730 | 长期免疫缺陷和慢性GVHD影响 |
| 超长期 | >D730 | 探索性描述，评估随访选择偏倚 |

固定时间点描述使用窗口内最接近目标日的合格记录；纵向模型使用全部合格观测。不能对不规则纵向数据做全局KNN填补或无边界线性插值。

## 5. 模块化质控设计

| 模块 | 核查规则 | 输出 |
|---|---|---|
| 原始文件治理 | 记录路径、大小、修改时间、哈希、编码、工作表和行列数；原始文件只读 | 数据版本清单、运行清单 |
| 结构质控 | 核查表头、列数、空列、重复列、CSV逻辑记录和物理行差异 | schema报告、异常行台账 |
| 主键与链接 | 标准化患者编号和机构编号；核查一对多、多对多、跨机构重复编号 | 患者主索引、跨表匹配报告 |
| 患者去重 | 清除标识符格式噪声；完全重复记录去重；不依赖姓名等直接标识自动合并 | 重复候选表、保留理由 |
| 时间逻辑 | 出生≤诊断≤预处理/移植≤事件/随访；所有事件日期与末次随访核对 | 时间冲突矩阵 |
| 临床变量 | 统一类别和缺失编码；检查ECOG、KPS、HCT-CI、年龄、身高、体重等范围 | 数据字典、类别映射表 |
| 移植逻辑 | 异基因应有供者信息；回输物、细胞剂量、植活、失败状态相互核对 | 移植一致性标记 |
| 项目标准化 | 统一中文/英文名、项目编码、星号前缀、全半角、大小写和同义词 | 标准检验词典 |
| 数值解析 | 原文、数值、比较符号、定性结果、检出限分别保存 | 标准化长表 |
| 单位与方法 | 同一指标按单位和检测方法分层；只在转换关系明确时换算 | 单位词典、转换日志 |
| 生物学合理性 | 比例<0或>100%、绝对计数<0为硬错误；其他极端值默认只标记 | 硬错误/软异常标记 |
| 重复检测 | 完全重复仅留一条；修订报告优先最新版；同日独立标本不盲目平均 | 重复分类表 |
| 报告解析 | 解析CD3、CD4、CD8、CD19、CD45RA/RO、CD25/CD28等；保留报告定位和置信度 | 免疫指标长表、解析失败原因 |
| NLP/规则验证 | 按年份和模板分层抽取至少300份报告，双人标注和争议裁决 | 金标准集、混淆矩阵 |
| 缺失机制 | 区分未检测、检测未报告、解析失败、不适用和真正缺失 | 缺失原因变量、缺失热图 |
| 观测过程 | 分析检测频率与住院、感染、GVHD、死亡的关系 | 检测强度曲线、观测概率 |
| 年度/批次漂移 | 比较年份、机构、仪器、方法、报告模板和单位分布 | 漂移报告、批次标记 |
| 结局一致性 | “发生=是”应有日期；事件日期不得晚于末次随访；空值不能解释为“否” | 结局质控表 |
| 截尾与竞争风险 | 定义末次随访、死亡、复发、非复发死亡和首次感染 | 风险集与截尾表 |
| 时间泄露 | Landmark暴露必须发生在Landmark前；结局从Landmark后计时 | 泄露审计报告 |
| 人工复核 | 关键冲突、异常和解析失败进入问题台账，记录决定人和决定日期 | 审核台账 |

## 6. 免疫报告的前置可行性闸门

工作簿内部审计确认，8,253条免疫重建报告中，`EXAM_FINDINGS`有值7,006条，其中7,001条符合标准百分数/单位模式，可定位约31,430个数值token；2条含非标准数字，需要专门规则；另3条虽有文本但无数字。`CONCLUSION`有值4,937条，但不承载数值。至少1,250条报告在现有工作簿的`EXAM_FINDINGS`和`CONCLUSION`中没有可恢复的定量值。结构化检验CSV主要是血常规和生化，免疫关键词记录仅约329条、108名患者。因此必须优先完成：

1. 为7,001条标准文本建立项目-数值-单位解析规则，并处理2条非标准数字；
2. 核对“检查名称识别的8,253条”与“报告类型标记的8,780条”之间527条差异；
3. 向数据提供方补取至少1,250条缺失报告的LIS结构化项目-数值-单位-参考范围或原始报告；
4. 获取marker/panel顺序及单位代码表、报告修订/作废规则和稳定脱敏关联键；
5. 确认CD3、CD4、CD8、CD19、NK等比例及绝对计数的字段语义。

现有文件足以启动7,001条报告的定量抽取和验证，但在1,250条缺失结果的来源、时间分布和患者分布明确之前，不能将缺失简单视为随机，也不能宣称完成全部报告的定量免疫重建图谱。

核心字段抽取的目标精确率和召回率为至少95%，定量数值与单位的精确匹配目标为至少98%。达不到阈值时不进入主要分析。

## 7. 已发现的关键数据问题

- CSV字段`DATA_STATUS`大量出现“*白蛋白”等项目名称，不能直接解释为有效/作废状态；
- 分子学复发和血液学复发字段目前全空，不能将空值视为未复发；
- “是否死亡”包含“放弃治疗”，须结合死亡日期和末次随访重新定义；
- 预处理强度约59%缺失，应依据预处理方案推导，并保留原始字段与推导字段；
- 22名移植患者没有免疫报告，1名没有结构化检验记录；这些患者必须出现在患者级纳排流程中；
- 免疫报告和结构化检验均存在随访至2026年的记录，需明确数据截点并检查移植后时间。

## 8. 数据流和产物

```text
原始文件（只读）
  -> 文件/结构审计
  -> 患者主索引与跨表链接
  -> 标准化临床表、检验长表、免疫报告表
  -> 规则质控与人工复核台账
  -> 患者级主队列
  -> 观测级免疫重建长表
  -> 按临床问题生成嵌套分析队列
  -> 分析数据冻结与版本记录
```

最终必须同时生成患者级和观测级两条流程，避免把患者数、报告数和检验明细数混为一谈。

主要交付物包括：

- 数据源与版本清单；
- 患者级纳排流程和检测记录级纳排流程；
- 数据字典、项目词典和单位词典；
- 患者主索引与跨表匹配报告；
- 日期、重复、异常、缺失和结局问题台账；
- 免疫报告金标准集与解析性能报告；
- 指标×时间窗患者覆盖率矩阵；
- 结局定义、风险集和截尾规则表；
- 最终队列清单及逐例排除原因；
- 可复现运行日志和冻结版本。

## 9. 错误处理与可恢复性

- 大CSV采用分块或列式查询，不整表载入内存；
- 每个阶段输出行数、患者数、唯一键数和哈希对账；
- 任务中断后从已完成阶段继续，不覆盖已冻结结果；
- 解析失败进入隔离表，不静默丢弃；
- 任何自动修正必须记录原值、标准值、规则版本和原因；
- 任何可能改变队列规模的规则均生成执行前后对账；
- GPU用于适合的本地NLP、嵌入或机器学习，不为简单CSV聚合强行使用GPU。

## 10. 验证与验收

### 10.1 自动验证

- 文件、字段、逻辑记录和患者数与源数据对账；
- 三表患者交集、差集和重复数可复现；
- 所有外键均指向患者主索引；
- 同一规则重复运行得到相同结果；
- 无时间泄露、负随访时间或事件晚于截尾等未解释错误；
- 主要输出中不存在无法追溯到原始记录的数据；
- 主要分析队列的每次纳入/排除均可逐例解释。

### 10.2 人工验证

- 按年份、报告模板和异常类型分层抽样；
- 核心免疫指标由两名临床人员独立标注，冲突由第三人裁决；
- 对关键事件日期、死亡状态和复发状态进行重点核查；
- 临床专家审核项目词典、单位换算和生物学硬阈值。

### 10.3 验收门槛

- 主队列患者编号和移植日期完整率100%；
- 跨表链接率及未链接原因明确；
- 核心免疫字段解析性能达到预设阈值；
- 所有硬逻辑错误为0或均有人工裁决；
- 纳排流程、问题台账、数据字典和冻结版本齐全；
- 原始数据未被修改。

## 11. 后续临床问题优先级

1. 描述CD3、CD4、CD8、CD19及可用亚群的典型恢复轨迹；
2. 评估年龄、供者来源、HLA、预处理、CD34+剂量和移植前MRD对轨迹的影响；
3. 评估D30/D60/D100免疫状态与后续CMV/EBV感染、GVHD、复发和死亡的关联；
4. 识别快速恢复、延迟恢复和免疫失衡等表型；
5. 区分免疫状态对结局的预测作用与感染/GVHD对免疫轨迹的反向影响。

正式建模前应预先指定一个主要免疫指标、一个主要时间窗和一个主要临床结局，其余作为次要或探索性分析。

## 12. 期刊分层与备援设计

项目采用同一数据底座上的三层证据路线。路线切换只能依据预设的数据可用性、验证条件和抽取性能门槛，不能依据显著性或P值选择故事。

### 12.1 Nature Medicine冲击路线

核心主张是：AML异基因HSCT后存在可重复的动态免疫重建状态；状态转换失败能够在传统临床变量之外提前识别感染、GVHD、复发或非复发死亡风险，并产生可解释的临床监测净获益。

该路线需要：

- 2018-2022发现队列和2023-2025时间验证队列；
- 至少一个独立外部中心，或约150-300例前瞻性标准化流式验证队列；
- 预设D30、D60、D100和D180 Landmark；
- 比较基础临床模型与“基础临床+动态免疫状态”模型；
- 同时报告区分度、校准、决策曲线、临床净获益和跨时间稳定性；
- 最好加入流式功能、细胞因子、单细胞或转录组等机制验证；
- 明确高风险状态对应的监测或干预建议，而不只输出风险分数。

没有外部/前瞻性验证和临床净获益时，本路线降级为探索性升级路线，不阻塞主体研究。

### 12.2 Nature Communications稳健主线

核心主张是：在大规模AML异基因HSCT队列中，建立高分辨率纵向免疫重建参考图谱，识别可重复的恢复轨迹和状态转换，解释其临床决定因素及与结局的时间关系。

最低证据包包括：

- CD3、CD4、CD8、CD19及可用分化/功能亚群的纵向参考曲线；
- 混合效应模型或广义加性混合模型估计非线性恢复；
- 快速、延迟和失衡恢复表型的稳定性验证；
- 年龄、供者、HLA、预处理、CD34+剂量和移植前MRD等决定因素；
- 至少一个可靠临床结局的Landmark或时间依赖分析；
- 2018-2022与2023-2025时间验证；
- 对检测频率、信息性缺失、竞争风险、年度漂移和时间泄露的系统审计；
- STROBE清单、数据访问说明、代码发布方案和可复现源数据表。

### 12.3 真实备援路线

若复发等结局无法补齐，仍保留三个互不依赖显著性的成稿出口：

1. 感染专病稿：D30-D100免疫恢复与后续CMV、EBV及其他感染；
2. 免疫轨迹稿：不依赖结局完整性的时间参考曲线、恢复速度和决定因素；
3. 数据方法稿：非结构化流式报告的结构化抽取、人工金标准和跨模板验证。

相关稿件不得产生实质性内容重叠；每篇稿件拥有独立主要问题、主要终点和分析计划。

### 12.4 内部止损门槛

| 闸门 | Nature Medicine路线 | Nature Communications路线 |
|---|---|---|
| 免疫覆盖 | T、B及至少一个功能/分化亚群 | 稳定覆盖T、B两条主要谱系 |
| 纵向密度 | 大量患者覆盖至少3个时间窗 | 允许部分患者仅1-2次，整体窗口覆盖充分 |
| 抽取性能 | 核心字段精确率/召回率至少95%，数值准确率至少98% | 相同 |
| 结局 | 感染、GVHD、复发、死亡中至少两个可靠且有日期 | 至少一个主要结局可靠 |
| 验证 | 独立外部队列或前瞻性标准化队列 | 时间验证为最低配置，外部验证优先 |
| 临床价值 | 超过传统临床变量并有决策净获益 | 可侧重时间图谱和领域重要进展 |
| 机制 | 强烈建议功能或多组学证据 | 可无实验机制，但需严谨动态分析 |

这些门槛是项目内部的预设决策规则，不代表期刊官方样本量要求。

### 12.5 实施优先级

先建设Nature Communications级、完全可复现的数据和质控底座；外部验证、前瞻性采样和机制实验作为可插拔模块加入Nature Medicine路线。任何升级模块失败都不得破坏已经冻结的主队列、质控规则和基础结果。
